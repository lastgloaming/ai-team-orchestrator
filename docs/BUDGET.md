# 预算

无已批准的真实预算。建议起点为每月 5 美元，日额度和调用数需作者确认。原型要求提供显式模型、费率、输入与输出上限、每日及每月金额和次数限制、并发及重试上限。低成本默认模型待官方文档复核；需要高性能模型时可以替换配置，同一 SQLite 台账只接受一种计费币种。

金额以对应币种的整数纳单位存储，1 美元或 1 元人民币均为各自的 10 亿纳单位。历史无币种的记录按其原计费方式标记为 USD，金额不重算。已有 USD 用量的台账拒绝 CNY，反之亦然。无用量的旧台账可在首次预留时使用 CNY。按最高适用费率向上取整，可保守忽略缓存折扣。按 UTC 统计。每个尝试先在同一事务中检查预算及并发并记录最坏费用，再发请求。必须配置经核对的 provider 输入上限作为保守估计，输出上限随请求发送。已知用量按实际 token 和保守费率记账；不确定请求保留最大预留。超过设置上限的响应会冻结后续调用，需核对供应商账单。请求超时与指定暂态 HTTP 错误才重试，每次占用独立预算。

`ORCHESTRATOR_STOP=1` 阻止新尝试，已发出的请求可能计费。进程崩溃留下的 active 记录保留费用和并发名额；作者授权的运维人员须确认旧进程已停止并使用 `Advisor.reconcile_terminated_attempt(reservation)` 将该记录标记为 uncertain，再恢复名额。生产需要提供受审计的对账入口和远端独立消费上限，工作流环境变量只在新进程启动时刷新。


## P4 单次人民币验证

`ORCHESTRATOR_P4_BILLING_CURRENCY=CNY` 时读取 `ORCHESTRATOR_P4_BUDGET_NANOYUAN`。现有 USD 配置仍读取 `ORCHESTRATOR_P4_BUDGET_NANODOLLARS`。未设置币种时沿用 USD。按作者核实的人民币峰值费率，deepseek-flash 以未缓存输入 2,000、输出 8,000 纳人民币/token 预留和记账，不依赖缓存命中或空闲折扣。单次测试预算最多 2,200,000,000 纳人民币，输出最多 64 token。工作流保留单次预留、跨重启的一次性标记、并发 1、零重试。配置和代码交付不构成付费授权。

2.20 元预算为 64 输出 token 预留 512,000 纳人民币后，最多容纳 1,099,744 个输入 token；再增加 1 个即超过预算。该数值是本地预算允许的输入上界。必须另行证明服务端的全部可计费输入上界，且该上界不高于上述预算允许值。`max_tokens=64` 限制生成输出。配置 `ORCHESTRATOR_P4_INPUT_TOKEN_BOUND` 之前须核对模型实际输入限制、服务端封装或隐藏 token、计费单位以及适用的最低收费和税费。此次云端重读三个官方页面均被代理拒绝，托管模型的实际输入限制和账单硬限额仍待验证。真实付费前须经作者另行批准。 [费率](https://api-docs.deepseek.com/quick_start/pricing/) · [接口](https://api-docs.deepseek.com/api/create-chat-completion/) · [用量](https://api-docs.deepseek.com/quick_start/token_usage/)
