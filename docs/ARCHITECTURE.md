# 架构

可信事件入口 → 协议解析 → 角色与动作校验 → SQLite 任务台账与事务性发件箱 → 已验证的执行端适配器。P1 使用离线入口和受控测试适配器。任务更新和发件箱写入同一事务，按稳定消息 ID 重放。执行端必须实现同一幂等键，才能安全恢复确认丢失。模型建议走独立接口，程序可以确定的操作直接走规则。ChatGPT 持有技术审核职责，作者保留最终决策。敏感动作进入 WAITING_AUTHOR，需在系统外单独审批并执行。

GitHub Actions runner 的本地磁盘随任务消失。生产应使用外部持久存储及原子事务，或单写者加带版本检查的持久台账和恢复队列。Actions concurrency 只能作为辅助，因为等待中的作业可能被替换。P1 的 SQLite 仅验证同一持久卷上的并发和重启，生产存储、投递适配器及身份桥接留待批准后验证。P0 查证见 [可行性报告](FEASIBILITY.md)。
